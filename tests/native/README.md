# AAPXS regression tests

Run `./tests/native/run-aapxs-lifecycle.sh` from the repository root. Requires clang++ and UBSan. The runner builds the actual transport/session/typed implementations in debug and release configurations, running the tests present at each stage of the patch series. Temporary binaries are cleaned up. macOS gets a clock_nanosleep compatibility shim; vptr sanitization is disabled because this partial link does not provide PluginInstance RTTI.

Request ID zero is covered for reply delivery, coexistence with ID one, timeout, and capacity reuse. The session retains its public size, API, and 255-slot limit; occupied slots are identified by their callback pointer.

Typed completion removes the request from the client map before invoking user code, keeping the request buffer owned until delivery returns. A regression callback destroys its own typed client. Failure snapshots also match request ID and address before completing a call.

Lifecycle tests cover typed/session destruction, 400 successive cancellations, late replies, stale callback tokens, concurrent cancellation during reply copying, reentrant callbacks, and legacy unsolicited host requests. Session gates live in a private sidecar to preserve the public ABI. Registrations are removed before request storage is freed. Binder connection/abort-registry races and real-time allocation/locking remain outside this fix.

Saturation tests cover 255 session callbacks and 1,024 global requests, immediate rejection without encoding or Binder fallback, subsequent capacity reuse, and encoding failure releasing its registration. Limits and public signatures remain unchanged. Legacy calls without an error callback receive their completion callback as the fallback failure notification.

Parameter scans retain transport errors for every count/parameter/enumeration read and publish only a complete successful result. Tests inject errors and short replies at every read, including the final read after partial progress, and check invalid counts, valid empty layouts and bounded names. Existing public getters retain their defaults.

MIDI clients send the existing length + UTF-8 plugin-ID record for compatibility with older services. New services prefer their instance metadata so older clients with empty/stale payloads select the correct preference key. Tests cover bounds, legacy Binder unknown lengths, actual handlers/reply size, and typed client success/error/short replies; only the JNI preference lookup is stubbed. SharedPreferences and mixed-version processes are not tested on-device. No public layout, API, opcode or wire format changes.

Connection/creation follow-up (2026-10-03, baseline `db829e89`): C++ public headers are unchanged. Missing Java-side connections and negative native creation results use the existing `AudioPluginException`; no wrapper containing an invalid instance ID is returned. Compiled public JVM signatures and descriptors were compared against an isolated build of that exact baseline and match, including default-argument entry points. Compiler-generated accessors for private members are implementation details.

Native connection reads and the library's JNI mutations share a private gate. Published native connection data retains its existing process lifetime; creation validates its pointer/proxy/validity before IPC and reports begin/end-create failures through the existing result. Host callbacks are published only after dispatcher initialization. Binder-death snapshots and host callbacks borrow the instance through private lifetime state; `PluginHost::destroyInstance()` waits for concurrent callbacks and defers reentrant deletion until the last callback exits. Tests cover concurrent retirement, nested reentrant retirement, late callbacks, and 10,000 connection replacement/lookups. Public connection-list mutations made by external callers still require caller coordination; this patch synchronizes the library-managed JNI path.

Four-ABI native builds, Kotlin compilation, and debug/release UBSan runs passed. Android instrumentation tests and their Gradle runtime-asset setup have been removed. The historical v0.11.2 tombstone and repeated remote-process death during begin/end creation have not been reproduced. Separate Binder request/typed abort-registry races remain outside these connection fixes.

Session-lock follow-up (#9c): encoding, pending callbacks, completion, and cancellation use the existing private per-session gate. The global encoding/callback lock is removed; only short registry/table bookkeeping locks remain shared. Tests stall both sending overloads in one session and require another session to send, complete, expire, cancel, and be destroyed before the stall is released. Same-session sends remain serialized, and send callbacks can deliver replies reentrantly. No public session fields, methods, size, layout, or wire records change. This removes cross-instance serialization; it does not make the transport real-time safe.

Synchronous-wrapper follow-up (#2, partial): generic typed and void wrappers now use the existing `callAndWait()` reply-wait timeout instead of indefinite `future.get()`/`wait()`. Their signatures, default error values, class fields, virtual methods, and wire records are unchanged; only inline bodies/comments change in the SDK header. The timeout value is captured before sending so synchronous completion can destroy the client without a subsequent member read. Compare SDK declarations and native object layouts with `./tests/native/check-aapxs-contracts.py ea4e2053` (Python 3 and clang++ required).

Tests cover no audio progress with a 20 ms timeout, subsequent success, late SysEx8 and Binder replies, service-death cleanup, 300 expiry/reuse cycles per wrapper, teardown after timeout, abandoned caller-capturing deserializers, and synchronous completion destroying the client. Waiting timeouts keep the call buffer owned until the transport replies, sweeps its timeout, or tears down; returning early and freeing a buffer still referenced by the transport would be unsafe. Capacity is therefore reclaimed by transport completion/expiry/teardown, not merely by returning from the wrapper.

This does not make synchronous calls safe on the audio thread. A synchronous send/IPC may block before reply waiting begins. An already-running deserializer is allowed to reference caller-owned memory, so `callAndWait()` still waits for that completion instead of returning while it uses the caller's locals. The regression verifies this retained lifetime contract; no new cancellation/result API or transport flag is introduced to change it.

The contract checker can also use existing NDK flags: `./tests/native/check-aapxs-contracts.py ea4e2053 --compile-commands androidaudioplugin/.cxx/tools/debug/arm64-v8a/compile_commands.json` (substitute the other ABI directory as needed). Baseline/current declarations and layouts match on the host and all four Android targets. No new public/protected methods or required aap-core library entry points are introduced by the SDK inline-body changes; clients must recompile to obtain the new wrapper behaviour.

Binder completion/abort follow-up: a request claims callback ownership under the channel mutex. Abort waits for an already-claimed callback to return (including reentrant abort), and queue advancement requires completed delivery. Request copying checks ownership under the same mutex. Tests cover failed dispatch racing with abort/replacement, 2,000 simultaneous completion/abort pairs, waiting for active/outer callbacks, nested blocking sends with queued work, reentrant abort, and late replies after request storage is invalidated. All added state is in the private .cpp Pending record; even the internal channel declarations stay unchanged. Typed abort-registry lifetime races and opposite-direction shared-memory use remain outside this fix.

#8 error/context API follow-up (baseline `5eb17d37`): native C++ API/ABI changes are intentional and require all affected consumers within an app to rebuild. `StateClientAAPXS` and `StandardExtensions::getStateSize()` return `Result<size_t>`; zero is a successful empty state, transport errors/negative sizes/short replies are failures. JNI raises the existing `AudioPluginException` on failure; JavaScript raises an error. The value-only C state extension bridge retains its original size/default contract for older callers.

The shared typed result handler now receives `(error, serialization, pluginOrHost)`. Both async parameter callbacks take a normal function pointer and `Result<T>`, distinguishing valid zero/default metadata from errors. The former private thread-local adapter and duplicated sender are removed. Preset/state async handlers and existing tests are migrated to the extra low-level context argument. No mutex, processing-thread dispatch, opcode, payload, extension URI, C extension ABI or AIDL declaration is added or changed. Existing processing-path locks remain pending the separate realtime redesign.

The parameter tests cover success/error context, exact error descriptions, short replies, valid zero metadata, nesting, concurrency, cancellation identity, teardown/late replies, self-destruction and unchanged legacy request/POD reply records. State-size tests cover zero/nonzero sizes, legacy four-byte replies, short/negative replies, rejection, death, timeout, late replies, local missing extensions, and the legacy C bridge. Both test the current recipient handlers with records constructed as an older client would send them.

Run `./tests/native/check-aapxs-wire-compatibility.py 5eb17d37` for byte-for-byte C extension/AAPXS/AIDL declarations and unchanged opcodes, shared capacities and actual recipient/reply handler bodies. This is a protocol/declaration check plus in-process wire fixtures, not an on-device mixed-version process test. Old peers that silently turn failures into successful zero values cannot expose an error they never reported. The old `check-aapxs-contracts.py` asserts C++ API/ABI compatibility and intentionally fails for this authorized C++ API break; its earlier validation instructions apply to the historical patches before this change.

Realtime follow-up (baseline `9e17764f`): [processing and extension architecture](../../docs/realtime-processing.md) describes the native API/ABI changes, application lock-free processing paths, bounded queues, worker ownership, suspension/silent-block behavior, notification coalescing and protocol compatibility. Earlier statements above about processing locks and unchanged native signatures describe the historical patches.

The new `rt-handoffs`, `rt-replies`, `rt-parameters` and `rt-processing` fixtures cover concurrent producers/backpressure, retained FIFO heads, wire-copy ownership, stale replies, stable-ID value cells during layout publication, actual local/remote processing and callback-driven teardown. `rt-processing` rejects application mutex/try-lock calls and C++ allocation/reclamation while processing; deliberate failing probes verify the detector. On macOS the runner builds and injects a temporary dyld guard library so libc++ mutex calls are observed. The guard and binaries are removed when the runner exits. To run a focused subset, use `AAPXS_TESTS="rt-handoffs rt-replies rt-parameters rt-processing" tests/native/run-aapxs-lifecycle.sh`.

No test depends on Android runtime assets or changes to `androidaudioplugin/build.gradle.kts`. Mixed-version APK/device audio stress tests remain unperformed.

The active-layout regression in `rt-processing` emulates an older service that returns Binder metadata and also queues redundant SysEx8 replies. It scans 80 parameters with two enumerations each, verifies legacy payload widths and complete publication, and requires a safe SysEx8 count barrier between Binder metadata reads. Processing continues while no metadata reply is available, and the same lock/allocation guards cover its audio blocks.

Eventfd follow-up (baseline `83026bdf`): the worker and DSP/control exclusion no longer sleep/poll every millisecond. Linux/Android uses preallocated nonblocking eventfds; macOS uses nonblocking pipes in the standalone harness. Workers block until publication, shutdown, or the earliest pending request deadline. Registration/cancellation explicitly rearm the deadline wait. Processing can issue notification writes but still does not acquire application locks or allocate C++ storage; kernel/scheduling latency remains outside the application guarantee.

`event-worker` exercises idle workers, publication racing with sleep, four concurrent producers, coalescing, idle shutdown, timeout without audio, earlier deadline insertion and cancellation returning the worker to an indefinite wait. Run `AAPXS_TESTS="event-worker rt-handoffs rt-processing" tests/native/run-aapxs-lifecycle.sh` for the focused subset. The processing fixture joins its notification/layout work before testing explicit suspension/resumption, avoiding an assumption that notification delivery means the subsequent layout scan has already finished.

The `rt-processing` fixture verifies that a layout request dispatched before service extensions are ready is retained and publishes real parameter metadata after setup wakes the worker. The standalone `event-worker` and `rt-handoffs` fixtures were also cross-compiled with NDK 29 for arm64/API 29 and executed in debug/release on the connected Pixel and Samsung devices. Those device primitive runs used the real eventfd backend without UBSan; the macOS suite uses UBSan. Temporary device executables were removed. No plugin APKs were installed or modified.
